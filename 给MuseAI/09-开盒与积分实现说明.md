# 09 盲盒开盒算法与积分（奉献值）结算 —— 代码级说明

对应代码：`backend_src/app/controller/api/v1/manghe/MangheController.php`（4280 行左右，全部行号以此文件为准）

## 0. 一句话版本

盲盒 = `eb_store_category` 的一行；奖品池 = `eb_store_product` 里 `tag` 落在 1..6 的商品；
权重抽奖在 `drawBoxProductByPublicOdds()`（:698-752）；扣款、定奖、发奖在**同一个 MySQL 事务**里（:1029-1240），
积分没有"冻结"这一步——没支付就不扣，扣了必然发奖。

## 1. 两张表决定一切

| 概念 | 表 | 关键列 |
|---|---|---|
| 盲盒（盒子） | `eb_store_category` | `price` 单抽价、`price3/price5/price10` 连抽价、`tag1..tag6` 稀有度权重、`product_id` 赠送抽奖 |
| 奖品（池子里的商品） | `eb_store_product` | `tag`(1..6 稀有度)、`price`、`cost`、`stock`、`postage`、`recovery_price` 等 |
| 用户开到的奖品 | `eb_user_box` | `status`(0=在背包 1=已回收/已用)、`tag`、`rand_num`(抽奖随机数，可审计)、`order_id` |

盒子取数：`MangheController.php:896` `$cate = Db::name('store_category')->where($where)->find();`
（盲盒没有独立的 cate 表，直接复用商城分类表，这是这套代码最省事也最反直觉的一点。）

## 2. 权重算法（公开概率模式）

`drawBoxProductByPublicOdds(array $cate, array $goods)` —— :698

1. 按 `product.tag` 把奖品分组：`$groups[$tag][] = $product`（tag 夹到 1..6，:702）
2. 权重表：`$weights[$tag] = (float)$cate['tag'.$tag]`，只收 >0 的；`$total` = 权重和（:709-715）
3. 掷骰：`$roll = mt_rand(1, (int)round($total * 1000));`（:718）
   —— 把权重放大 1000 倍变整数，规避浮点误差；`$roll` 会写进 `eb_user_box.rand_num`（:673），抽奖可复查
4. 累加游标 `$cursor += round($weight*1000)`，`$roll <= $cursor` 命中该 tag（顺序 1→6，:721-727）
5. 池内等概率：`$pool[array_rand($pool)]`（:750）——**同一稀有度内部不再加权**
6. 空池降级：先往低 tag 找（:731-737），再往高 tag 找（:739-745）；全空返回 null → 整个下单失败回滚

开关：`hasPublicOddsConfig($cate)`（:684）—— `tag5` 与 `tag6` 都 <=0 时判定"未启用公开概率"，
退回老的**幸运值模式**（:1140-1180，按 `user.lucky_num` 与价格档位比较，`$lucky_num_old >= $v`，:1146）。
新项目建议只用公开概率模式：把 `tag5/tag6` 配成非 0 即可启用。

批量开盒：`createBoxItemsByPublicOdds()`（:648）循环 `num` 次独立抽取，每次独立 `mt_rand`，
没有"连抽保底"，没有权重衰减。

## 3. 稀有度命名与回收比例

## 4. 积分（元气）语义映射

本项目内部叫「积分 / 元气」，字段是 `eb_user.integral`、明细表 `eb_user_bill`。
晨祷叫「奉献值」，语义一一对应：**1 奉献值 = 1 积分**，¥1 = 1 奉献值 就是本项目的"充值送积分"。

两个系统配置行（`backend_src/public/install/crmeb.sql` 里已有种子）：
- `integral_ratio`（:7721，默认 `"1"`）＝ 积分抵用比例，1 积分抵多少元
- `integral_max_num`（:7810，默认 `"200"`）＝ 单次下单积分抵扣上限，0 为不限

抵扣计算 `useIntegral()`（:1493-1518）：
```
$integral = min(user.integral, integral_max_num)      // 上限截断（:1503-1507）
$deductionPrice = bcmath(integral * integral_ratio, 2) // :1508
若抵扣价 < 应付：应付 -= 抵扣价，扣 integral 个积分
否则：抵扣价 = 应付，扣 ceil(应付 / integral_ratio) 个积分（:1514）
```
全程 `bcmath` 两位小数，不用浮点。

**扣减时机**：只在支付成功分支里（:1058-1082）：`bcDec(user.integral)` + 写 `eb_user_bill`
（`pm=0, category='integral', type='manghe', link_id=order_id`）。
=> 没有冻结表、没有预扣、没有"支付失败退积分"逻辑，因为未支付时一个积分都没动。
这就是你「售罄不扣分」那条规则的同一思路：**所有扣减都发生在成功的临界点，且与发奖同事务**。

事务边界：`Db::startTrans()`（:1029）→ 改订单状态 / 扣余额 / 扣积分 / 核销券 / 写 `eb_user_box` /
组装赠送 → 任一步抛异常即 `rollback`（:1240 附近 catch）。所以不会出现"扣了积分没给奖品"。

## 5. 回收（奖品换回积分）

`recovery()`（:2559-2650）：
1. 单件回收价优先级：`store_product.recovery_price` > `cost` > `price * recoveryRateByTag(tag)`，
   最后 `max(1, round(...))` 保底 1 积分（:2580-2587）
2. 事务内：选中 `eb_user_box.status=0` 的前 N 条 → 置 1（:2603-2608）；
   `eb_user.integral` 自增（:2621）；写 `eb_user_bill`（`pm=1, type='recovery'`，:2625-2637）
3. 数量不足整单失败（:2604-2606 `抛 "拥有数量小于选择数量"`）

## 6. 保底/统计

`pity_info()`（:3562）：取最近 100 条 `eb_user_box`（`is_jiqiren=0`，排除机器人），
统计"连续非稀有"次数返回给前端做展示。**只是展示，没有真正的保底出奖逻辑**。
要真保底，得在 `drawBoxProductByPublicOdds` 里加计数器判定。

## 7. 你要接的时候，三件最要紧的事

1. **权重列不存在**：见 `补列-盲盒概率与回收.sql`，2025-06 备份的 `eb_store_category` 只有 `tag1..tag4`，
   `eb_store_product` 缺 `is_recovery / recovery_price / reference_price / recovery_discount`。
   全仓 SQL 里**没有任何一个脚本**建这些列，是当年在生产库上手工加的。
2. **空池会整单失败**：某个 tag 权重 > 0 但该 tag 没有商品，会降级找相邻 tag；
   若 1..6 全空则返回 null → 下单回滚。上线前必须校验每个启用的 tag 都有货。
3. **权重是"每抽独立"**：`num=10` 就是 10 次独立 `mt_rand`，期望值与单抽一致，
   想做成"十连必出 Epic"要在 `createBoxItemsByPublicOdds` 循环里加约束。
