## C. Docker Compose 实测情况（老实说）

**没有做过从干净 checkout 的实测。** 原因：本机没有生产库、没有真实 `.env`，生产服务器 2026 年已到期释放。
文件层面是齐的，但只能给"读配置得出的结论"，不能给"跑通过的结论"：

- `deploy/docker/php81-fpm/Dockerfile`：`php:8.1-fpm-bookworm` + `pdo_mysql mysqli bcmath gd(freetype,jpeg) intl zip pcntl opcache sockets` + `pecl redis-6.1.0` + composer
- `deploy/docker/php81-fpm/php.ini`：`memory_limit=512M`、`max_execution_time=300`、`post_max_size=50M`
- `docker-compose.yml` 五服务：`mysql:8.0`(crmeb-mysql，卷 `/opt/crmeb-prod/mysql_data`，`127.0.0.1:3306:3306`)、`redis:7-alpine`、soketi、`eccomall-php81-fpm`、`nginx:1.25-alpine`
- nginx 站点：`deploy/nginx/host/vivodraw.com.conf`

⚠️ **一个坑，必须在纯净机器上改**：compose 注释写的是「Host 网络：127.0.0.1 指向 host MySQL/Redis」，
即 PHP 容器用 host 网络、`.env` 里 `[DATABASE]HOSTNAME=127.0.0.1`。
在全新机器上用 compose 自带的 mysql 服务时，PHP 容器里 127.0.0.1 指的是容器自己 → 连不上。
要么把 `[DATABASE]HOSTNAME` 改成服务名 `mysql`（同时 `[REDIS]REDIS_HOSTNAME=redis`），要么保持 host 网络但 MySQL 装在宿主上。

配置模板（无任何真实密钥）：`backend_src/.example.env`、
`deploy/.env.example`（仅 `MYSQL_ROOT_PASSWORD/MYSQL_DATABASE/MYSQL_USER/MYSQL_PASSWORD`）。

## D. 域名：`eccobuy.com` 还是 `vivodraw.com`？

**正式域名 = `https://vivodraw.com`。** 依据：

1. `mobile-app/app.json` 的 `expo.extra.ApiBaseUrl` / `WebBaseUrl` 都是 `https://vivodraw.com`
2. `mobile-app/eas.json` 里 `development` / `development-simulator` / `preview` 三个 profile 的 env 也都是 `https://vivodraw.com`
3. 线上实际就是 vivodraw.com
4. `api.eccobuy.com` 与 `eccobuy.com` 实测 **DNS 不解析**（`The remote name could not be resolved`）→ 死域名

只在 `eas.json` 的 `production` profile 里出现 `https://api.eccobuy.com` / `https://eccobuy.com`，
那是早期规划留下的占位配置。**你打包前必须把 production 的 env 改成自己的域名/API**，否则线上 App 会连一个解析不了的域名。
