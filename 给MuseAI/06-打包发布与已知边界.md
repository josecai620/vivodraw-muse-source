# 06 · 打包发布与已知边界

## 一、EAS 打包

`eas.json` 已存在，profile：

| profile | 说明 | 后端基址 |
| --- | --- | --- |
| `development` | dev client，内部 | `https://vivodraw.com` |
| `development-simulator` | iOS 模拟器 | 同上 |
| `preview` | 内部预览 APK / IPA，channel `preview` | 同上 |
| `production` | 商店包，channel `production`，`autoIncrement: true` | `https://api.eccobuy.com` |

命令：

```bash
npm i -g eas-cli
eas login
eas init                 # 会生成属于你账号的新 projectId
npm run eas:build:preview:android    # 出 APK 自测
npm run eas:build:prod               # 商店包
```

### 打包前必须改的两处

1. `app.json` → `extra.eas.projectId`：现在是原项目的 `fa436af4-60f7-4dfa-ab3d-add1f9124d34`，**你打包必须换成自己的**，否则 build 会挂或推到别人项目下
2. `app.json` → `ios.bundleIdentifier` / `android.package`：现在都是 `com.eccomall.app`。
   - **和原 App 合并成一个 App** → 保持不动
   - **做独立上架的新 App** → 改成你自己的，例如 `com.morningprayer.app`

### ⚠️ 一个需要和项目方确认的配置不一致

`eas.json` 里 **production** profile 的后端基址是 `https://api.eccobuy.com`（Web 基址 `https://eccobuy.com`），
而 `development` / `preview` 和 `app.json extra` 都是 `https://vivodraw.com`。

两边不是同一套域名。正式包要用哪个，**先问清楚再用**，别自己改。

## 四、已知边界与坑

1. **只有前台**：没有后端、数据库、管理后台。所有真实数据都要连线上 `https://vivodraw.com`。
2. **语言只有 en 和 zh-TW**（繁体），没有简体包。要加简体得新建 locale 文件并注册到 `lib/i18n/index.ts`。
3. **通知中心有 mock 开关**：`app/points/notifications.tsx` 里 `USE_DEV_MOCK`，真数据靠接口。
4. **新架构开启**（`newArchEnabled: true`）：引入第三方原生库前确认兼容 RN 0.81 + 新架构。
5. **Web 端没有原生能力**：SecureStore 退化 localStorage、推送不可用。做 Web 预览时功能要能优雅降级。
6. **静态导出**（`web.output = "static"`）：新增路由会自动生成对应静态页；动态参数页注意 `generateStaticParams`。
7. **中文文件名**：仓库里有 `scripts/优化网页首屏.cjs`、`lib/会员头像框素材.ts` 这类中文名文件，Linux/CI 上要注意 UTF-8 locale，别随手改名（会破坏引用）。
