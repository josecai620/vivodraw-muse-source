# 05 · 晨祷功能接入方案（核心）

## 目标

在现有 VivoDraw App 里增加「晨祷」模块：今日晨祷 / 经文 / 每日定时提醒 / 打卡记录，与商城共用账号与通知。

**原则：只加不改。** 新代码全部放新文件；必须动的只有两处（加 tab、加 i18n key），且都是纯新增行。

---

## 一、路由怎么加（两种，二选一或都做）

### 方案 A：独立路由组（先做这个，最安全）

```
app/prayer/
├── _layout.tsx      # Stack 容器
├── index.tsx        # 今日晨祷（默认页）
├── archive.tsx      # 往期晨祷 / 经文库
└── settings.tsx     # 提醒时间设置
```

路由自动生成：`/prayer`、`/prayer/archive`、`/prayer/settings`。
不需要改 `app/_layout.tsx`（它已经用 expo-router 的 Stack，新目录自动可导航）。

入口先挂在「我的」页：`app/(tabs)/profile.tsx` 里加一张卡片 → `router.push("/prayer")`。

### 方案 B：进底部 tab（体验更好，但要调样式）

改 `app/(tabs)/_layout.tsx`，现有 5 个 `<Tabs.Screen>` 在第 **176–232 行**，追加一个：

```tsx
<Tabs.Screen
  name="prayer"
  options={{
    title: t("tabs.prayer"),
    tabBarIcon: ({ focused }) => (
      <TabIcon Icon={TabPrayerIcon} label={t("tabs.prayer")} focused={focused} />
    ),
  }}
/>
```

注意三点：

1. 图标要自己加：`components/shared/TabNavIcons.tsx` 里按现有风格加一个线条图标（28px、`strokeWidth` 1.65/1.9、`color` 由外部传入）
2. 5 个 tab 变 6 个会挤压，label 字号和间距在 `tabIconStyles` / `tabBarLabelStyle` 里要一起调
3. 中文 label 比英文长，两种语言都要试

**建议：先 A 上线，稳定后再评估 B。**

## 二、提醒通知（复用现成的 `lib/native/push.ts`）

已有能力（不用重写）：

| 函数 | 位置 | 作用 |
| --- | --- | --- |
| `registerForPush()` | `lib/native/push.ts:38-85` | 建 Android channel、申请权限、拿 Expo push token、存本地 |
| `getCachedPushToken()` | `lib/native/push.ts:87-93` | 读缓存 token |
| `sendLocalNotification(title, body, data)` | `lib/native/push.ts:96-105` | 立刻弹一条本地通知（`trigger: null`） |
| 前台展示策略 | `lib/native/push.ts:20-28` | `setNotificationHandler`：前台也弹横幅 + 响声 |

### 晨祷要的是「每天固定时间提醒」——加一个定时函数

```ts
// 建议新建 lib/native/prayer-reminder.ts，不要改 push.ts 的既有导出
import * as Notifications from "expo-notifications";
import { SchedulableTriggerInputTypes } from "expo-notifications";

export async function scheduleDailyPrayer(hour: number, minute: number) {
  // Android 单独建一个高优先级 channel，别复用 "default"
  await Notifications.setNotificationChannelAsync("prayer", {
    name: "晨祷提醒",
    importance: Notifications.AndroidImportance.HIGH,
    sound: "default",
  });

  return Notifications.scheduleNotificationAsync({
    content: {
      title: "晨祷时间到了",
      body: "今天的经文在等你",
      sound: "default",
      data: { screen: "/prayer" },   // 点通知跳转用
    },
    trigger: {
      type: SchedulableTriggerInputTypes.DAILY,
      hour,
      minute,
      channelId: "prayer",
    },
  });
}
```

配套操作：

- 取消：`Notifications.cancelScheduledNotificationAsync(id)`
- 列表：`Notifications.getAllScheduledNotificationsAsync()`
- 把返回的 `id` 存进 AsyncStorage（key 如 `prayer_reminders`），改时间前先取消旧的，避免重复提醒堆叠

### 权限

- iOS / Android 13+ 都要运行时权限：`registerForPush()` 里已经做了（`requestPermissionsAsync`）
- `app.json` 已声明 Android `POST_NOTIFICATIONS`，不用再改
- **本地定时通知在 Expo Go 里基本可用；远程推送必须用 dev build / 正式包**

### 远程推送（可选，第二阶段）

- `lib/native/push.ts:74` 有现成占位：`// TODO(send-to-backend): POST /api/user/device`
- 后端接口目前**不存在**，要先和后端约定，再把这个 TODO 补上
- `getExpoPushTokenAsync` 需要 EAS `projectId`（`app.json` 里那个属于原项目，你要自己发包就换成自己的）

## 三、数据从哪来

**没有后端接口时，先本地优先**：

| 数据 | 存储 | key 建议 |
| --- | --- | --- |
| 提醒时间 / 开关 | AsyncStorage | `prayer_settings` |
| 已调度的通知 id | AsyncStorage | `prayer_reminders` |
| 打卡记录 / 连续天数 | AsyncStorage | `prayer_checkins` |
| 今日经文内容 | 先内置静态 JSON（`lib/prayer/content.ts`），后接接口 | — |

有后端后再补 `lib/api/prayer.ts` + `hooks/usePrayer.ts`，页面代码基本不用改（hook 内部切换数据源）。

建议的接口形态（和后端对齐时用）：

```
GET  /api/prayer/today        -> { date, title, scripture, content, audioUrl? }
GET  /api/prayer/archive?page  -> 分页往期
POST /api/prayer/checkin      -> 打卡
GET  /api/prayer/checkin      -> 连续天数、累计
POST /api/user/device         -> 上报 push token
```

## 四、多语言

新增文案必须同时加：

- `lib/i18n/locales/en.json`
- `lib/i18n/locales/zh-TW.json`

目前只有这两种语言（没有简体中文包）。key 用 `prayer.*` 前缀，例如 `prayer.today.title`。

## 五、与商城融合的三个入口（建议按这个顺序做）

1. **「我的」页卡片**：`app/(tabs)/profile.tsx` 顶部加「今日晨祷」入口 + 打卡天数
2. **首页横幅**：`app/(tabs)/index.tsx` 顶部加一条晨祷 banner（复用现有 banner 组件样式）
3. **通知中心合并**：`app/points/notifications.tsx` 已有分类过滤器，加一个「晨祷」分类即可（这个文件里有 `USE_DEV_MOCK` 开关，真数据来自接口）

再进一步（需要后端支持）：打卡换积分、晨祷任务进积分任务体系。**这属于第二阶段，先别动积分商城代码。**

## 六、深链

`app.json` 的 `scheme = "points-mall"`。

- 外部打开：`points-mall://prayer`
- 通知点击跳转：通知 `data` 里带 `{ screen: "/prayer" }`，在根布局监听 `Notifications.addNotificationResponseReceivedListener`，读到后 `router.push`
