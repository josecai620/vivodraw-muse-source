# 11 · 导入数据库的坑：crmeb.sql 少了 64 张表

这一份是我在做"能不能一键装起来"时挖出来的，比 10 号文档更要紧，先看这个。

## 结论先说

`base/crmeb.sql`（官方安装包，173 张表）**不包含盲盒和积分商城整套表**。
我把它和 2025-06 生产库结构（275 表）逐表比对：有 **64 张 `eb_*` 表只存在于生产库，仓库 23 个 SQL 脚本里没有任何一个创建它们**——当年是直接在生产库上建的。

只导入 `crmeb.sql` 的结果：后台能进，但一开盲盒/积分商城就 `Table 'xxx.eb_user_box' doesn't exist` / `eb_store_integral_product doesn't exist`。

## 缺的都是什么

按用途分四组（共 64 张）：

1. **盲盒主链路**：`eb_user_box`（用户抽到的奖品记录，含 `tag`、`rand_num`、`status`）、`eb_box_order`、`eb_user_manghe_set`（盲盒全局设置）、`eb_user_choujiang_set`（抽奖设置）。
2. **积分商城整套**（约 35 张）：`eb_store_integral_product` 及 attr/attr_value/attr_result/description/cate/brand/label/reply/reply_comment/rule/specs/virtual/stock_record/log/relation/unit/coupon/ensure、`eb_store_integral_cart`、`eb_store_integral_category`、`eb_store_integral_visit`，以及回收/开奖相关：
   `eb_store_integral_product_huanqu_log`、`..._huanqu_log_unique`、`..._huanqu_set_price`、`..._huanqu_set_zhong`、`..._kaijiang_log`、`..._kaijiang_shaidan`、`..._kaijiang_shaidan_comment`、`..._kaijiang_shaidan_praise`、`..._recovery_log`、`eb_store_integral_order_status_kaijiang`。
3. **运营/杂项**：`eb_store_activity`、`eb_store_activity_relation`、`eb_store_newcomer`、`eb_store_delivery_order`、`eb_store_order_writeoff`、`eb_system_timer`、`eb_system_form`、`eb_system_form_data`、`eb_system_sign_reward`、`eb_system_user_apply`、`eb_user_jiqiren`、`eb_user_jiqiren_touxiang`、`eb_out_interface`、`eb_integral_category`、`eb_store_product_category`、`eb_store_product_category_brand`、`eb_store_product_words`、`eb_supplier_*`、`eb_user_bank`、`eb_user_relation`、`eb_video`、`eb_video_comment`、`eb_wechat_qrcode*`。
4. **更早期的 fa_*（38 张）**：Ecshop 时代的抽奖/会员/物流遗留表，本项目代码不读，**我没有打包进去**，你要复刻历史数据才需要。


## 两个必须知道的技术细节

1. **27 张表是 utf8mb3**，`crmeb.sql` 里的是 utf8mb4。混用会在联表或字符串比较时报
   `Illegal mix of collations (utf8mb3_general_ci,IMPLICIT) and (utf8mb4_general_ci,COERCIBLE)`。
   我在「补全」文件里跟了一段 `ALTER TABLE ... CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;`（新库是空表，秒完成）。若你是从旧库整库迁，先备份再跑这段。
2. **`eb_store_category.tag1..tag6` 是 decimal(10,3)**，不是整数，权重可以带小数（比如 0.5）。代码里 `round(total*1000)` 放大取整，所以权重精度到千分之一，配 0.001 也生效。
